## AGENTS.md (Task 3)

```markdown
# AGENTS.md

Lab assignments for the AI4SE 2026 course (AI for software engineering). This repository is a fork of the course repository; new weeks arrive by pulling from upstream.

## Layout

- Each week has its own folder named `Week_NN_Topic/` (for example `Week_03_Prompting/`, `Week_08_Dissecting/`).
- Assignments live in `Week_NN_Topic/Assignments/Task_N/Task_N.md`. A week may also have a `readme.md` in `Assignments/` with context for all its tasks. Bonus tasks use folder names like `Task_10_Bonus/`.
- Solutions live outside `Assignments/`, in the week folder. Week 06 uses one folder per task (`Week_06_Implementation/Task_N/`). Week 08 puts outputs straight into the week folder with a task prefix (`task1_screenshot.jpg`, `task3_explanation.md`).

## Solving a task

- Read the task's `Task_N.md` and the week's `readme.md` first.
- Produce exactly what the task's `OUTPUT` section asks for. No extra files, reports or helper scripts.
- Scripts written for a task sit with that task's outputs and write their results (data, charts) there too.
- Some tasks are about configuring the coding assistant itself (system prompt, slash commands and similar). Those outputs are screenshots or short notes, not code.

## Reports

Reports must read as written by a person: first person, plain verbs, real numbers and file names, short paragraphs, no stock AI phrasing, no em dashes, no closing summary. Keep a report to about 250 words of prose unless the assignment asks for more.

## Git

Never commit or push without explicit permission from the user. Commit messages are short, in the style of `Week 06 solution: tasks 1-5`.
```

## .claude/skills/explain-concept/SKILL.md (Task 5, skill)

```markdown
---
name: explain-concept
description: Explain a course concept (RAG, embeddings, ADR, chunking, system prompt, ...) in a few plain sentences with one small example from this repository. Use when the user asks what a term or idea from the AI4SE course means.
---

# Explain a concept

Explain the concept the user asked about so that someone completely new to the topic understands it.

1. Say what it is in one or two plain sentences, without complicated words. If a technical term can't be avoided, explain it in a few words.
2. Find one small, real example in this repository: a file, script or report from an earlier week where the concept is used. Name the file and say in one sentence how it shows the concept. If nothing in the repo fits, say so and give a short everyday example instead.
3. If it helps, add one sentence on why it matters for the course or for coding assistants.

Keep the whole answer under about 120 words. No headings, no bullet lists, no tables. Don't solve any task while explaining.
```

## .claude/rules/report-file-names.md (Task 8, rule)

```markdown
# Date and time in report file names

Whenever you create a new report or other Markdown file in this repo, add the current date and time to the end of its file name in the form `_YYYY-MM-DD_HH-MM`, for example `task8_report_2026-11-22_14-35.md`.

- Get the real local time by running `date +%Y-%m-%d_%H-%M` right before creating the file. Don't guess it.
- Use hyphens in the time, not colons (colons aren't allowed in Windows file names).
- This applies only to new files. Don't rename existing files, and don't apply it to configuration files (`CLAUDE.md`, `AGENTS.md`, `SKILL.md`, files in `.claude/`) or to code.
```
