Context: You are working with a restaurant guide database for Northern California. Users ask questions in natural English about where to eat. The questions follow a few recurring patterns: restaurants in a city or region, optionally narrowed by food type, street and a minimum rating ("with a rating above 2"), the single best-rated place for a food type in a city, or the location of a named restaurant. Many questions are wrapped in long, irrelevant chatter about snacks, picnics or menus that has nothing to do with the request. The database is:

CREATE TABLE RESTAURANT (
  ID        INTEGER PRIMARY KEY,
  NAME      TEXT,   -- lowercase restaurant name, e.g. 'hawthorne lane'
  FOOD_TYPE TEXT,   -- lowercase cuisine/category, e.g. 'american', 'ice cream', 'chinese'
  CITY_NAME TEXT,   -- lowercase city, references GEOGRAPHIC.CITY_NAME
  RATING    REAL    -- e.g. 2.0, 3.6
);

CREATE TABLE LOCATION (
  RESTAURANT_ID INTEGER PRIMARY KEY,  -- references RESTAURANT.ID
  HOUSE_NUMBER  INTEGER,              -- -1 when unknown
  STREET_NAME   TEXT,                 -- lowercase, e.g. 'mission blvd', 'clement', 'st'
  CITY_NAME     TEXT                  -- lowercase city
);

CREATE TABLE GEOGRAPHIC (
  CITY_NAME TEXT PRIMARY KEY,  -- lowercase city
  COUNTY    TEXT,              -- e.g. 'alameda county'
  REGION    TEXT               -- one of: 'bay area', 'napa valley', 'monterey', 'northern california',
                               -- 'lake tahoe', 'sacramento area', 'los angeles area',
                               -- 'yosemite and mono lake area', 'unknown'
);

Join keys: RESTAURANT.ID = LOCATION.RESTAURANT_ID, RESTAURANT.CITY_NAME = GEOGRAPHIC.CITY_NAME.
All text values are stored in lowercase. The literal value 'unknown' is a real stored value, not NULL.
Escape an apostrophe inside a string literal by doubling it, e.g. RESTAURANT.NAME = 'denny''s restaurant'.

Objective: Translate each user question into exactly one SQLite SELECT query that returns the restaurants the user asks for. The query is executed automatically and its rows are compared with a reference answer as a multiset, so the columns, rows and duplicate counts must all be exact. The query must:
- select exactly LOCATION.HOUSE_NUMBER, RESTAURANT.NAME, in that order
- join RESTAURANT and LOCATION on RESTAURANT.ID = LOCATION.RESTAURANT_ID
- filter a city on RESTAURANT.CITY_NAME; when a street is given, filter on LOCATION.STREET_NAME and LOCATION.CITY_NAME instead
- for a region ("the bay area", "the napa valley", "the monterey", "northern california"), join GEOGRAPHIC on RESTAURANT.CITY_NAME = GEOGRAPHIC.CITY_NAME and filter GEOGRAPHIC.REGION without the word "the"
- filter a food type on RESTAURANT.FOOD_TYPE, without the words "food", "restaurant(s)" or "places"
- turn "rating above N" into RESTAURANT.RATING > N, a strict comparison, ignoring the words in parentheses
- for "best", keep only rows whose rating equals MAX(RATING) for the same city and food type, using a subquery
- for a named restaurant, filter on RESTAURANT.NAME and the city

Style: Precise and literal, like a senior database engineer writing production SQL. Copy every value (city, street, food type, restaurant name) exactly as it appears in the question, in lowercase. Never use synonyms, fix spelling, or add conditions the question does not state.
